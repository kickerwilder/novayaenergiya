# Чат-консультант: серверная прослойка

Сайт статический, а ключ к Gemini API должен оставаться секретом, поэтому бот живёт отдельно: маленький Node-сервис (Node 20+). Сайт обращается к нему по `POST /chat`, сервис считает подбор станций и спрашивает модель. **Числа считает код** (`assets/calc.js`, тот же модуль, что и на сайте), модель только ведёт диалог и вызывает инструменты.

## Что где лежит

| Файл | Назначение |
| --- | --- |
| `core.js` | ядро: чистая функция `handle(Request, env) → Response` (Web-стандарт), эндпоинты `POST /chat` и `GET /health`, CORS, лимиты, цикл инструментов, сборка карточек |
| `provider.js` | адаптер провайдера: сейчас Gemini (нативный `generateContent`, чистый `fetch`, SOCKS5/HTTP-прокси). Чтобы заменить провайдера, меняется только он |
| `tools.js` | инструменты модели: `select_stations`, `get_station`, `list_loads`, `handoff_to_manager`; считают через `assets/calc.js` |
| `kb.js` | загрузка базы знаний `data/kb.json` (с сайта по `KB_URL`, кэш 5 минут, либо с диска) |
| `prompt.md` | системная инструкция консультанта; правила, список «НЕ ПОДТВЕРЖДЕНО» и FAQ дописываются из базы знаний автоматически |
| `server.js` | запуск на своём компьютере или на VPS (Node `http`, читает `bot/.env`) |
| `cloud.js` | тонкая обёртка под облачную функцию (Яндекс Облако), экспортирует `handler` |
| `example.env` | пример настроек. Реальный `bot/.env` в `.gitignore` и не коммитится |

Данные для бота собирает `python scripts/build_bot_kb.py` (входит в `python scripts/build_all.py`): `data/kb.json` — публичный файл с моделями, ценами, приборами, правилами и FAQ. Вес, габариты и другие неподтверждённые данные в нём вынесены в список `unconfirmed`: бот цифр по ним не называет.

## Переменные окружения

| Переменная | Что это |
| --- | --- |
| `PROVIDER_API_KEY` | ключ Google AI Studio (секрет!). Для бота лучше отдельный проект и отдельный ключ |
| `PROXY_URL` | SOCKS5 или HTTP-прокси (`socks5://логин:пароль@хост:порт`), если сервер в регионе, откуда Gemini недоступен. Пусто — прямое соединение |
| `MODEL`, `FALLBACK_MODEL` | модели Flash / Flash-Lite класса; запасная используется при ошибке, лимите или таймауте основной. Актуальные имена: официальная страница моделей Gemini API |
| `KB_URL` | адрес `data/kb.json` на сайте (кэш 5 минут: обновление цен не требует передеплоя бота). Пусто — читается `../data/kb.json` с диска |
| `ALLOWED_ORIGINS` | адреса сайта через запятую, которым разрешён CORS (сейчас GitHub Pages, позже — свой домен) |
| `DAILY_CAP` | общий суточный лимит запросов (по умолчанию 500) |
| `RATE_LIMIT`, `RATE_WINDOW_S` | лимит на одного клиента (по умолчанию 20 запросов за 600 с). Клиент определяется хэшем IP с солью, IP нигде не хранится и не логируется |
| `LOG_QUESTIONS` | `1` — писать в лог текст вопросов (без IP и метаданных) |
| необязательные | `PORT` (8787), `TRUST_PROXY=1` (за nginx), `THINKING_LEVEL` (`minimal`), `TIMEOUT_MS` (20000), `RATE_SALT`, `PROVIDER_BASE_URL` |

Для тестов дополнительно `TEST_TRACE=1`: в ответ добавляется `trace` с результатами инструментов. **В рабочем режиме не включать.**

## Локальный запуск

```
cd bot
npm install            # undici и socks (нужны только для прокси)
copy example.env .env  # заполнить PROVIDER_API_KEY и PROXY_URL
node server.js         # слушает :8787
```

Связь с Gemini через прокси проверяет `node proxy_check.js` (10 запросов «Ответь ОК», печатает страну выхода прокси и результат, секреты не печатает).

Проверка: `GET http://localhost:8787/health` отвечает `{"ok":true}` без обращения к провайдеру. Чат с сайта: откройте страницу сайта с `?chat=local` (или `?chat=local:ПОРТ`), в `ALLOWED_ORIGINS` должен быть адрес, с которого открыта страница.

Лимиты: тело запроса ≤ 8 КБ, ≤ 20 сообщений, каждое ≤ 500 символов, ответ модели ≈ 600 токенов, температура 0,3, таймаут 20 с, не больше 4 итераций вызова инструментов.

## Тесты

Сценарии в `tests/bot_cases.json`, запуск `scripts/test_bot.py` против реальных локальных серверов (основной, с недоступным провайдером, с ценой 0 в базе знаний и с жёстким лимитом запросов). Подробности и команды запуска — в начале `scripts/test_bot.py`. Сверка расчётов сайта до и после выноса в `calc.js`: `node tests/calc_equivalence.js`.

## Деплой (хостинг выбирается после тестов)

Ограничение: запросы к Gemini должны выходить через разрешённый регион, поэтому нужен прокси или сервер за пределами РФ. Cloudflare Workers **не подходит**: через внешний прокси он не ходит.

**VPS (проще всего).** Подойдёт дешёвый VPS с Node 20.
1. Скопируйте на сервер папку `bot/`, файл `assets/calc.js` (положите рядом с `core.js` как `calc.js`; для этого есть `node bot/pack.js`, он соберёт папку `bot/dist` без секретов) и выполните `npm install --omit=dev`.
2. Создайте `.env` по `example.env` (ключ вводится только на сервере). Задайте `KB_URL` (адрес `data/kb.json` на сайте), `ALLOWED_ORIGINS`, `TRUST_PROXY=1`, если перед сервисом nginx.
3. Запустите через systemd или `pm2` (`node server.js`), поставьте перед ним nginx с HTTPS (Let’s Encrypt). Адрес сервиса впишите в `CHAT_URL` в `assets/app.js`.

**Яндекс Облако (Cloud Functions).** Создайте функцию Node 20 с точкой входа `cloud.handler`, загрузите содержимое `bot/dist`, значения переменных задайте в консоли (ключ — как секрет), включите публичный HTTP-вызов. Прокси для запросов к Gemini нужен и там.

После выбора хостинга: откройте `/health` с телефона в российской сети; если не открывается, перенесите на другой хостинг без переписывания кода.

## Смена модели, ключа, прокси

- Модель: поменять `MODEL` (и `FALLBACK_MODEL`) и перезапустить сервис; код не меняется.
- Ключ или прокси: поменять `PROVIDER_API_KEY` или `PROXY_URL` и перезапустить. В чаты и в репозиторий их не вставлять.
- Другой провайдер: заменить реализацию `generate()` в `provider.js` (ядру нужен только результат `{content, text, calls, finishReason}`).

## Данные и логи

- **Обновление цен и каталога.** После обновления выполните `python scripts/build_all.py` и опубликуйте сайт: бот сам подтянет новый `data/kb.json` по `KB_URL` не позже чем через 5 минут, передеплой не нужен.
- **Логи вопросов.** При `LOG_QUESTIONS=1` каждый вопрос клиента пишется в стандартный вывод процесса (`journalctl -u имя-службы` для systemd, `pm2 logs`, журнал функции в облаке). Только текст вопроса, без IP.
- **Лимиты исчерпаны.** При превышении лимита клиента или суточного лимита бот отвечает вежливо и просит позвонить или написать на почту (`handoff: true`), сырые ошибки клиенту не показываются. Суточный счётчик и счётчики клиентов хранятся в памяти и обнуляются при перезапуске. Если квота самого провайдера исчерпана (HTTP 429), включается запасная модель; при постоянных 429 увеличьте квоту в Google AI Studio или поднимите `DAILY_CAP` осторожно.

## Безопасность

- Ключ, адрес и логин прокси живут только в `bot/.env` и в переменных окружения хостинга; в клиентском коде, репозитории и логах их нет.
- CORS только для `ALLOWED_ORIGINS`; запросы с чужого Origin получают 403.
- Бот не принимает заказы, оплату и персональные данные: клиента направляют на телефон и почту.
- Перед запуском для клиентов нужна политика конфиденциальности по 152-ФЗ.
