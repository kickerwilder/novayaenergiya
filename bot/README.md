# Чат-консультант: серверная прослойка

Сайт статический, а ключ к Gemini API должен оставаться секретом, поэтому бот живёт отдельно: маленький Node-сервис (Node 20+). Сайт обращается к нему по `POST /chat`, сервис считает подбор станций и спрашивает модель. **Числа считает код** (`assets/calc.js`, тот же модуль, что и на сайте), модель только ведёт диалог и вызывает инструменты.

## Что где лежит

| Файл | Назначение |
| --- | --- |
| `core.js` | ядро: чистая функция `handle(Request, env) → Response` (Web-стандарт), эндпоинты `POST /chat` и `GET /health`, CORS, лимиты, цикл инструментов, сборка карточек |
| `provider.js` | выбор провайдера по `PROVIDER` и адаптер Gemini (нативный `generateContent`, чистый `fetch`, SOCKS5/HTTP-прокси); проверка настроек при старте |
| `provider_openai.js` | адаптер OpenAI-совместимого API (`chat/completions`): перевод истории и вызовов инструментов туда и обратно (`PROVIDER=openai`) |
| `llm.js` | вызов модели для любого провайдера: одна повторная попытка при 429 и 5xx (с учётом `Retry-After` и общего бюджета времени), запасная модель, учёт токенов в логе (только счётчики) |
| `dotenv.js` | чтение `bot/.env` |
| `tools/eval_cases.js` | оценка моделей при выборе провайдера: прогоняет `tests/bot_cases.json` и печатает таблицу (кейс, результат, время, токены, стоимость); в боевом запуске не используется |
| `tools.js` | инструменты модели: `select_stations`, `get_station`, `list_loads`, `handoff_to_manager`; считают через `assets/calc.js` |
| `kb.js` | загрузка базы знаний `data/kb.json` (с сайта по `KB_URL`, кэш 5 минут, либо с диска) |
| `prompt.md` | системная инструкция консультанта; правила, список «УТОЧНЯЕТСЯ» и FAQ дописываются из базы знаний автоматически |
| `server.js` | запуск на своём компьютере или на VPS (Node `http`, читает `bot/.env`) |
| `cloud.js` | тонкая обёртка под облачную функцию (Яндекс Облако), экспортирует `handler` |
| `example.env` | пример настроек. Реальный `bot/.env` в `.gitignore` и не коммитится |

Данные для бота собирает `python scripts/build_bot_kb.py` (входит в `python scripts/build_all.py`): `data/kb.json` — публичный файл с моделями, ценами, приборами, правилами и FAQ. Вес, габариты и другие данные, которые уточняются, вынесены в список `clarify`: бот цифр по ним не называет.

## Переменные окружения

| Переменная | Что это |
| --- | --- |
| `PROVIDER` | `gemini` (по умолчанию) или `openai` (любой OpenAI-совместимый API `chat/completions`) |
| `PROVIDER_API_KEY` | ключ провайдера (секрет!); для Gemini это ключ Google AI Studio, для бота лучше отдельный проект и отдельный ключ |
| `PROVIDER_BASE_URL` | адрес API: для `openai` обязателен и берётся из личного кабинета провайдера (к нему добавляется `/chat/completions`); для Gemini обычно не нужен |
| `PROVIDER_EXTRA_BODY` | JSON с дополнительными полями запроса к модели (например, отключение режима рассуждений у конкретной модели); объекты сливаются, `null` удаляет поле. Некорректный JSON: бот не запускается, ошибка называет переменную |
| `PROVIDER_EXTRA_HEADERS` | JSON с дополнительными заголовками запроса (нужны части провайдеров); `null` или пустая строка убирает заголовок |
| `LLM_USE_PROXY` | `1` (по умолчанию): запросы к модели идут через `PROXY_URL`; `0`: к модели напрямую, а `PROXY_URL` остаётся только для Telegram |
| `PROXY_URL` | SOCKS5 или HTTP-прокси (`socks5://логин:пароль@хост:порт`) ТОЛЬКО для исходящих запросов к LLM и Telegram (сервер в Москве: напрямую они недоступны). Пусто — прямое соединение. Остальной трафик прокси не использует |
| `MODEL`, `FALLBACK_MODEL` | модели Flash / Flash-Lite класса; запасная используется при ошибке, лимите или таймауте основной. Актуальные имена: официальная страница моделей Gemini API |
| `KB_URL` | адрес `data/kb.json` на сайте (кэш 5 минут: обновление цен не требует передеплоя бота). Пусто — читается `../data/kb.json` с диска |
| `ALLOWED_ORIGINS` | адреса сайта через запятую, которым разрешён CORS. По умолчанию `https://novaya-energy.ru` и `https://www.novaya-energy.ru` |
| `ALLOW_LOCALHOST` | `1` — разрешить запросы с `http://localhost` и `127.0.0.1` (только локальная разработка и тесты; на сервере `0`) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_MANAGER_CHAT_ID` | уведомление менеджеру в Telegram при передаче обращения (отправка `sendMessage` через `PROXY_URL`, вебхук не используется). Chat id: `node tg_chat_id.js` |
| `DAILY_CAP` | общий суточный лимит запросов (по умолчанию 500) |
| `RATE_LIMIT`, `RATE_WINDOW_S` | лимит на одного клиента (по умолчанию 20 запросов за 600 с). Клиент определяется хэшем IP с солью, IP нигде не хранится и не логируется |
| необязательные | `PORT` (8787), `HOST`, `TRUST_PROXY=1` (за Caddy или nginx), `THINKING_LEVEL` (`minimal`), `TIMEOUT_MS` (20000), `RATE_SALT`, `MAX_OUTPUT_TOKENS` (600), `RETRY_PAUSE_MS` (1000), `RETRY_MAX_WAIT_MS` (3000) |

Для тестов дополнительно `TEST_TRACE=1`: в ответ добавляется `trace` с результатами инструментов. **В рабочем режиме не включать.**

## Локальный запуск

```
cd bot
npm install            # undici и socks (нужны только для прокси)
copy example.env .env  # заполнить PROVIDER_API_KEY и PROXY_URL
node server.js         # слушает :8787
```

Прокси проверяет `node proxy_check.js`: печатает только схему прокси (`http` или `socks5`) и итог по адресам Telegram и Gemini, без логина, пароля и хоста; `node proxy_check.js --gemini` добавляет 10 запросов «Ответь ОК» к Gemini API. Рабочий вариант проверен с HTTP-прокси; SOCKS5 у некоторых провайдеров зависает.

Проверка: `GET http://localhost:8787/health` отвечает `{"ok":true}` без обращения к провайдеру. Чат с сайта: откройте страницу сайта с `?chat=local` (или `?chat=local:ПОРТ`), в `ALLOWED_ORIGINS` должен быть адрес, с которого открыта страница.

Лимиты: тело запроса ≤ 16 КБ; **новое сообщение клиента ≤ 500 символов** (только для него возвращается «Сообщение длиннее 500 символов»); история диалога: сервер берёт последние 12 сообщений (старые отбрасываются без ошибки), ответы ассистента в истории молча обрезаются до 800 символов; ответ модели ≈ 600 токенов, температура 0,3, таймаут 20 с, не больше 4 итераций вызова инструментов. Виджет отправляет только `role` и `text` последних 12 сообщений (ответы бота до 800 символов), карточки и служебные данные в историю не попадают. Лимиты на клиента (число запросов за окно) и суточный лимит от истории не зависят.

## Тесты

Сценарии в `tests/bot_cases.json`, запуск `scripts/test_bot.py` против реальных локальных серверов (основной, с недоступным провайдером, с ценой 0 в базе знаний и с жёстким лимитом запросов). Подробности и команды запуска — в начале `scripts/test_bot.py`. Сверка расчётов сайта до и после выноса в `calc.js`: `node tests/calc_equivalence.js`.

## Деплой

**Основной путь: VPS с Docker и Caddy, пошаговая инструкция в [DEPLOY.md](DEPLOY.md)** (`Dockerfile`, `docker-compose.yml`, `deploy/Caddyfile`; порт бота только на 127.0.0.1, HTTPS и закрытие поддомена от индексации в Caddy). Ниже прежние варианты.

Ограничение: запросы к Gemini должны выходить через разрешённый регион, поэтому нужен прокси или сервер за пределами РФ. Cloudflare Workers **не подходит**: через внешний прокси он не ходит.

**VPS (проще всего).** Подойдёт дешёвый VPS с Node 20.
1. Скопируйте на сервер папку `bot/`, файл `assets/calc.js` (положите рядом с `core.js` как `calc.js`; для этого есть `node bot/pack.js`, он соберёт папку `bot/dist` без секретов) и выполните `npm install --omit=dev`.
2. Создайте `.env` по `example.env` (ключ вводится только на сервере). Задайте `KB_URL` (адрес `data/kb.json` на сайте), `ALLOWED_ORIGINS`, `TRUST_PROXY=1`, если перед сервисом nginx.
3. Запустите через systemd или `pm2` (`node server.js`), поставьте перед ним nginx с HTTPS (Let’s Encrypt). Адрес сервиса впишите в `CHAT_URL` в `assets/app.js`.

**Яндекс Облако (Cloud Functions).** Создайте функцию Node 20 с точкой входа `cloud.handler`, загрузите содержимое `bot/dist`, значения переменных задайте в консоли (ключ — как секрет), включите публичный HTTP-вызов. Прокси для запросов к Gemini нужен и там.

После выбора хостинга: откройте `/health` с телефона в российской сети; если не открывается, перенесите на другой хостинг без переписывания кода.

## Смена модели, ключа, прокси

- Модель: поменять `MODEL` (и `FALLBACK_MODEL`) и перезапустить сервис; код не меняется.
- Ключ или прокси: поменять `PROVIDER_API_KEY` или `PROXY_URL` и перезапустить. В чаты и в репозиторий их не вставлять.
- Другой провайдер: переменные `PROVIDER=openai`, `PROVIDER_BASE_URL`, `PROVIDER_API_KEY`, `MODEL` и перезапуск; код не меняется. Пошагово: `DEPLOY.md`, раздел «Смена провайдера модели». Ядру нужен только результат `{content, text, calls, finishReason}`, его возвращают оба адаптера.

## Данные и логи

- **Обновление цен и каталога.** После обновления выполните `python scripts/build_all.py` и опубликуйте сайт: бот сам подтянет новый `data/kb.json` по `KB_URL` не позже чем через 5 минут, передеплой не нужен.
- **Логи.** Тексты диалогов, контакты и IP клиентов в логи не пишутся; в лог попадает только вид сбоя (`chat_error: http 503`, `tg_error: timeout`).
- **Лимиты исчерпаны.** При превышении лимита клиента или суточного лимита бот отвечает вежливо и просит позвонить или написать на почту (`handoff: true`), сырые ошибки клиенту не показываются. Суточный счётчик и счётчики клиентов хранятся в памяти и обнуляются при перезапуске. Если квота самого провайдера исчерпана (HTTP 429), включается запасная модель; при постоянных 429 увеличьте квоту в Google AI Studio или поднимите `DAILY_CAP` осторожно.

## Безопасность

- Ключ, адрес и логин прокси живут только в `bot/.env` и в переменных окружения хостинга; в клиентском коде, репозитории и логах их нет.
- CORS только для `ALLOWED_ORIGINS`; запросы с чужого Origin получают 403.
- **Персональные данные.** До отправки в LLM и в уведомление менеджеру текст клиента (все его сообщения, включая историю диалога) проходит через `maskPII` (`bot/pii.js`, применение в `bot/core.js`, функция `chat`). Ответы бота и контакты менеджера не маскируются. Подробности ниже, раздел «Маскирование персональных данных».
- **Уведомление менеджеру.** При `handoff = true` (ответ с «Уточните у менеджера», контактами менеджера или вызовом `handoff_to_manager`) уходит одно сообщение в Telegram: суть вопроса (замаскированная) и время, без ссылки на диалог; один раз на диалог. Сбой Telegram не влияет на ответ клиенту.
- **Прокси.** `PROXY_URL` используют только запросы к LLM (`provider.js`) и к Telegram (`telegram.js`).
- Локальный запуск и тесты `scripts/test_bot.py`: в `.env` или в окружении нужен `ALLOW_LOCALHOST=1`.
- Бот не принимает заказы, оплату и персональные данные: клиента направляют на телефон и почту.
- Перед запуском для клиентов нужна политика конфиденциальности по 152-ФЗ.

## Маскирование персональных данных

Порядок: e-mail, номера с подписью («паспорт», «ИНН», «СНИЛС»), телефоны, остальные номера, адреса, ФИО. Повторный вызов ничего не меняет, метки не ломаются. Тексты клиента и найденные данные в логи не попадают.

| Что | Метка | Примеры записи (вымышленные) |
| --- | --- | --- |
| e-mail | `[EMAIL]` | `name@example.com` |
| телефон | `[ТЕЛЕФОН]` | `+7 978 111-22-33`, `8 (978) 111-22-33`, `978 111 22 33`, `9781112233` |
| банковская карта, 13-19 цифр | `[НОМЕР КАРТЫ]` | `4111 1111 1111 1111`, `4111-1111-1111-1111`, `4111111111111111`, `3782 822463 10005` |
| паспорт РФ, 10 цифр | `[ПАСПОРТ]` | `4512 345678`, `45 12 345678`, `паспорт 4512345678`, `серия 4512 номер 345678` |
| ИНН (10 и 12 цифр), СНИЛС (11), расчётный счёт (20) | `[НОМЕР]` | `ИНН 123456789012`, `123-456-789 01`, `40817810123456789012`, `40817 810 1 2345 6789012` |
| адрес | `[АДРЕС]` | `ул. Тестовая, д. 5, кв. 12`, `проспект Мира 10, корп. 2`, `д. 5, кв. 12`, `кв. 12`; индекс только как `индекс 298100` (метка заменяет цифры) |
| ФИО | `[ФИО]` | `Иванов Иван Иванович`, `Иванов И.И.` |

Адрес маскируется, когда есть маркер улицы (`ул.`, `улица`, `пр-т`, `проспект`, `пер.`, `переулок`, `ш.`, `шоссе`, `б-р`, `бульвар`, `наб.`, `набережная`, `пл.`, `площадь`, `мкр.`, `микрорайон`) вместе с названием и номером дома (`д. 5`, `дом 5`, `5А`, `5/2`), а также последующие `кв.`, `корп.`, `стр.`, `подъезд`, `этаж`, `офис`. Город и регион сами по себе не маскируются.

**Что не маскируется** (проверено тестами по данным каталога, 637 фраз, ложных срабатываний 0): цены (в том числе `1 500 000 ₽`), мощность (Вт), ёмкость (Вт·ч), габариты (`45х30х28`), вес, годы, проценты, время, артикулы и коды моделей (`z1600-5000-L`, `ZF16-2002.6`), обычная речь («на улице», «для квартиры», «в частном доме», «СНТ», «гараж», «квартира» как слово).

**Ограничения эвристики** (маскирование намеренно осторожное: лучше замаскировать лишнее, чем пропустить данные, но и обычные числа не трогать):
- Десять цифр подряд без подписи, начинающиеся с 3-9 (например `4512345678`), считаются телефоном, а не паспортом: приоритет у телефонной функции. Со словом «паспорт» рядом это `[ПАСПОРТ]`, со словом «ИНН» это `[НОМЕР]`. Десять цифр подряд, начинающиеся с 0-2, без подписи получают метку `[ПАСПОРТ]` (это может быть и ИНН: данные скрыты в любом случае, метка приблизительная).
- Цифры в разных записях склеиваются только по известным раскладкам (карта 4-4-4-4, 4-6-5, 4-6-4; паспорт 4+6 и 2-2-6; СНИЛС `123-456-789 01`; счёт 5-3-1-4-7, 4-4-4-4-4, 5-5-5-5). Номер с необычной разбивкой («4111 11111111 1111») или с буквами и словами внутри не распознаётся.
- Карта с группами 4-4-4-4 маскируется, если проходит проверку Луна или перед ней стоит слово «карта»; перечень «круглых» чисел (`2800 3800 5000 8600`) картой не считается. Карта с опечаткой и без слова «карта» может остаться незамаскированной.
- Паспорт записи «dddd dddddd» (4+6 цифр через пробел) не маскируется, если первая четвёрка «круглая» (1000, 4600): так выглядят мощность или ёмкость и цена без единиц. Такой паспорт ловится только со словом «паспорт».
- СНИЛС без дефисов (`112 233 445 95`) маскируется только со словом «СНИЛС»: иначе перечень из четырёх чисел (`150 300 100 60`) принимался бы за номер.
- Адрес без маркера улицы (только «Тестовая 5», «посёлок Дачный, 12») и без номера дома («улица Мира») не маскируется. Название улицы строчными буквами без пометки `д.` или `дом` после полного слова «улица» не считается адресом («на улице холодно 5»). Почтовый индекс без слова «индекс» не маскируется.
- Названия, цифры и адреса в ответах бота и в контактах менеджера не проверяются: маскируется только то, что пишет клиент.
- Эвристика не заменяет рекомендацию клиенту не писать личные данные в чат (подсказка есть в виджете, правило есть в `bot/prompt.md`: бот не повторяет метки и напоминает про контакты на сайте).
