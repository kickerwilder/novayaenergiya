# Каталог электростанций — статический сайт

Сайт без сборщика и сервера: HTML, CSS и JavaScript без фреймворков. Открывается и двойным щелчком по `index.html`, и по HTTP.

## Структура файлов

    index.html          разметка страницы
    assets/styles.css   стили
    assets/app.js       логика каталога, hero и блок SETTINGS (валюта, подписи, ссылка кнопки связи)
    assets/reveal.js    появление блоков при прокрутке (IntersectionObserver)
    data/catalog.js     const DATA: 29 моделей (комбинаций мощности и ёмкости), 42 версии корпуса (править только скриптом)
    data/prices.js      const PRICES: цены по кодам версий (меняется скриптом import_prices.py)
    data/charge.js      const CHARGE: мощность зарядного устройства по кодам версий (для времени зарядки)
    img/, fonts/        изображения и локальные шрифты
    scripts/            служебные Python-скрипты
      import_prices.py  загрузка цен из CSV или таблицы владельца (XLSX) в data/prices.js
      split.py          одноразовый скрипт, которым index.html был разнесён по файлам
      update_data_v2.py скрипт обновления data/catalog.js (ресурс, пик, розетки, приборы); повторный запуск безопасен
      process_media.py  обработка фото и видео владельца в img/ (нужны Pillow и ffmpeg)
      update_media.py   привязка фото и схем к data/catalog.js (запускать после process_media.py)

Порядок подключения в `index.html`: `assets/reveal.js`, `data/catalog.js`, `data/prices.js`, `data/charge.js`, `assets/app.js` (обычные `<script src>`, без `type=module`).

## Как поменять цены

Цена задаётся для каждой версии корпуса отдельно. Код версии: `Z1600-4200-D` — мощность 1600 Вт, ёмкость 4200 Вт·ч, `D` — тёмный корпус, `L` — светлый на колёсах. Всего 42 кода.

### Вариант 1: прямо из таблицы владельца (.xlsx)

Файл с ценами лежит вне репозитория (например, папка `prices` рядом с ним) и в git не попадает: `*.xlsx` и `prices.csv` добавлены в `.gitignore`. Обновление цен:

        python scripts/import_prices.py "путь\к\таблице.xlsx"

Какой лист читать, в какой строке заголовки и как называются колонки с кодом и с ценой, скрипт берёт из файла настроек `import_config.json`. По умолчанию он ищется в папке `prices` рядом с репозиторием (`..\prices\import_config.json`), другой путь задаётся ключом `--config`. Файл настроек в репозиторий не входит, образец лежит в `scripts/import_config.example.json`:

        {
          "sheet": "ИМЯ_ЛИСТА",
          "header_row": 1,
          "code_column": "КОЛОНКА_С_КОДОМ",
          "price_column": "КОЛОНКА_С_ЦЕНОЙ"
        }

- `sheet`: имя листа с данными;
- `header_row`: номер строки с заголовками (с 1);
- `code_column`: точный заголовок колонки с кодом версии (например `Z1600-4200-D`);
- `price_column`: точный заголовок колонки с итоговой ценой в рублях.

Колонки ищутся по имени заголовка, а не по номеру. Файл открывается с `data_only=True`, то есть берутся значения, сохранённые Excel в последний раз: перед запуском откройте таблицу в Excel, дайте пересчитаться формулам и сохраните. Нужен `pip install openpyxl`.

Цена округляется **вверх** до целого рубля (`Decimal`, `ROUND_CEILING`): 36803,412 → 36804, 74342,04 → 74343. Если в колонке кода или цены есть пустые значения, не найден файл настроек или заголовок, скрипт останавливается с понятной ошибкой и ничего не записывает.

### Вариант 2: из простого CSV

1. Подготовьте таблицу из двух колонок: **код** и **цена** (первая строка с заголовками необязательна). Формат цены любой привычный: `129900`, `129 900`, `129900 ₽`, `129 900,00`. Копейки в CSV не допускаются: нужны целые рубли.
2. Сохраните как CSV (UTF-8) и запустите из корня проекта (нужен Python 3):

        python scripts/import_prices.py цены.csv

### Отчёт и проверка

Чтобы только проверить файл, ничего не записывая, добавьте `--check`. Скрипт печатает отчёт: какие из 42 кодов не найдены, какие коды лишние, какие цены нулевые, нечисловые, неоднозначные (например `129.900`) или повторяются с разными значениями. Если проблемы есть, `data/prices.js` не изменяется: исправьте таблицу и запустите снова. Флаг `--allow-partial` записывает файл, оставляя для проблемных кодов прежние цены. После импорта откройте `index.html` и проверьте цены в карточках.

`0` или отсутствие цены на сайте показывается как «Цена по запросу». Пока файла с ценами нет, в `data/prices.js` стоят нули. Сноска «Цены указаны в рублях и не являются публичной офертой» появляется только когда на странице есть хотя бы одна цена; её формулировку согласуйте с владельцем.

Правьте `data/prices.js` и `data/catalog.js` только скриптами: так не нарушится формат и кодировка.

Валюта, подписи и ссылка кнопки связи — в блоке `SETTINGS` в начале `assets/app.js`
(например, `contactHref: "https://t.me/ваш_ник"` или `"tel:+79990000000"`; пусто — кнопка скрыта).

## Данные карточек и подбор (data-v2)

- **Ресурс батареи:** 2000+ циклов заряда (после них ёмкость не менее 80 %), по паспорту изделия. Число в hero берётся из строки «Ресурс батареи» каталога.
- **Гарантия:** в `SETTINGS` (`assets/app.js`): `warrantyText` (показывается под ценой в каждой карточке и в блоке «Контакты» рядом со сроком доставки) и `warrantyExtra` (доплата за продление, ₽). Основная цена не меняется.
- **Приборы** (`DATA.loads` в `data/catalog.js`): `watts` — мощность при работе (на кнопке и для проверки станции), `avg` — в среднем (для расчёта часов; если не указано, равна `watts`), `start` — пусковая мощность, Вт (если не указано, пусковой нагрузки нет).
- **Пик станции** = 2 × номинала (по паспорту изделия, до 0,3 с). Станция подходит, если `power` не меньше суммы `watts` выбранных приборов и пик не меньше наибольшей пусковой нагрузки среди выбранных. Время работы считается по сумме `avg`: ёмкость × 0,85 ÷ средняя нагрузка. «Суммарная нагрузка» в подборе остаётся суммой `watts`.
- **Одна розетка:** поле `maxSocket` версии — предел одной розетки. Для каждой группы розеток это меньшее из значений: «до N Вт» из каталога, мощность станции, 2,2 кВт для 10 А, 3,5 кВт для 16 А; берётся максимум по группам. Если суммарная нагрузка больше, в карточке появляется подсказка включать приборы в разные розетки.
- **Зарядка:** `data/charge.js`, ключ — код версии, поля `acW` (Вт) и `basis` (`passport` или `estimate`). Время 0–80 % = 0,8·E/(P·0,9), 0–100 % = E/(P·0,9)·1,2, где E — ёмкость в Вт·ч, P — `acW`; округление до 0,1 ч. У версий без записи показывается «Время зарядки уточняется». Не выдумывайте значения: добавляйте только по данным владельца.
- **Карта моделей:** «гармошка» по 4 группам ёмкости (`DATA.groups`) на всех ширинах, открыта одна группа за раз. В группе кнопки мощностей с ценой «от …», пометкой корпуса и часами работы холодильника; станции, которым не хватает мощности, серые.
- **Модель** на сайте — это комбинация мощности и ёмкости (сейчас 29; 22 с тёмным корпусом, 20 со светлым, 13 с обоими). Все счётчики считаются из `DATA.combos`, вручную их не вписывайте.
- Правки каталога делаются скриптом `scripts/update_data_v2.py`; не правьте `data/catalog.js` вручную.

## Фото и видео

Исходники лежат **вне репозитория**, в папке `photos` рядом с ним (`..\photos`), и никогда не коммитятся. Нужны 11 файлов:

| Файл | Что это | Куда попадает |
| --- | --- | --- |
| `hero.mp4` | видео для шапки | `img/hero.mp4` (без звука, 1280 px, H.264, до 2 МБ) и постер `img/hero-poster.jpg` (кадр около 4-й секунды) |
| `black-station.jpg` | тёмный корпус, «ящик» | `img/photo-black.jpg` |
| `black-cabinet.jpg` | тёмный корпус, «шкаф» | `img/photo-cabinet.jpg` |
| `white-station.jpg` | светлый корпус на колёсах | `img/photo-white.jpg` |
| `scene-house.jpg`, `scene-room.jpg`, `scene-pair.jpg` | сцены для блока «Где пригодится» | `img/scene-*.jpg`; из `scene-pair.jpg` ещё `img/og.jpg` (1200×630) для ссылок в мессенджерах |
| `diagram-black-box.jpg`, `diagram-black-cabinet.jpg` | схемы портов тёмных версий | `img/diagram-black-*.jpg` (ширина 900 px) |
| `diagram-white-4.jpg`, `diagram-white-5.jpg` | схемы портов светлых версий (2×10 А + 2×16 А и 3×10 А + 2×16 А) | `img/diagram-white-*.jpg` |

Как обновить:

1. Положите файлы в `..\photos` (или укажите другую папку аргументом).
2. `pip install Pillow`. Для видео нужен ffmpeg: он есть в PATH или в пакете `imageio-ffmpeg` (`pip install imageio-ffmpeg`, лучше во временное окружение вне репозитория). Без ffmpeg видео копируется как есть, и скрипт пишет его вес.
3. `python scripts/process_media.py` (или `python scripts/process_media.py D:\другая\папка`). Скрипт идемпотентный, печатает размеры и вес результата. Недостающие исходники пропускаются, прежние файлы остаются. Чтобы пересобрать только один файл, например новую сцену: `python scripts/process_media.py --only scene-pair.jpg` (остальные файлы и `og.jpg` не меняются).
4. `python scripts/update_media.py`: прописывает фото и схемы в `data/catalog.js` (поля `img`, `diagram`, `dh`, `DATA.photos`).

Фото, видео и схемы иллюстративные: на странице есть подписи «Видео иллюстративное» и «Изображение иллюстративное». Видео в шапке стоит на паузе вне экрана, не запускается автоматически при `prefers-reduced-motion` и включённой экономии трафика (тогда виден постер).

## Выбор корпуса

В шапке три кнопки: «Все», «Тёмный корпус», «Светлый на колёсах». Числа моделей считаются из `data/catalog.js`. В карточке у моделей с двумя вариантами корпуса есть две кнопки с миниатюрой, названием и ценой версии; если вариант один, показывается пометка «Только …».

## Цена с доставкой

Цены на сайте включают доставку, поэтому рядом с каждой ценой (в карточке и в переключателе корпуса) стоит подпись «с доставкой», в hero написано «от N ₽ с доставкой», а в сноске про цены: «Цена с доставкой». Для цены 0 («Цена по запросу») подпись не показывается. Текст подписи — `SETTINGS.deliveryText` в `assets/app.js`. Из условий доставки на сайте указан только срок: «Срок доставки в Россию: около 25 дней» (hero, карточка «Доставка» в блоке «Контакты», сноска в футере со словами «Срок ориентировочный.»). Регионы, перевозчики и прочие условия добавлять только по данным владельца.

## Контакты

Телефон и e-mail лежат прямо в `index.html` (липкая полоса сверху, hero, блок «Контакты», футер, нижняя панель на мобильных) в виде ссылок `tel:` и `mailto:`. Чтобы сменить контакт, замените `+79787280002` / `+7 978 728-00-02` и `apv0050@gmail.com` в `index.html`, а также `contactHref` в `SETTINGS` (`assets/app.js`).

Реквизиты и режим работы на странице пока не показываются (решение владельца).

## Когда будут реквизиты

Данные берутся только от владельца, ничего не выдумывать. Что добавить:

- **Наименование организации или ФИО ИП**, **ИНН**, **ОГРН или ОГРНИП**, **адрес**. Для ООО ещё **КПП**. Место: блок `<footer class="foot">` в `index.html`, новый абзац `<p class="req">` под строкой `foot-brand` («НОВАЯ ЭНЕРГИЯ»), например: `ИП Фамилия И. О. · ИНН … · ОГРНИП … · Адрес: …`.
- **Режим работы**. Место: блок `<section id="contacts">` в `index.html`, внутри `<div class="contacts">` ещё один `<div><h3>Режим работы</h3><p>…</p></div>`. Сетка сейчас в две колонки, для трёх блоков поменяйте `grid-template-columns` у `.contacts` в `assets/styles.css` на `repeat(3,minmax(0,1fr))` и уберите `max-width`.
- Если нужен адрес и в блоке «Контакты», добавьте такой же `<div>` с заголовком «Адрес».

Пока данных нет, держите места пустыми, а не пишите догадки: на публикуемой версии не должно быть текста-заглушек. Проверка перед публикацией: `grep -rn "TODO_" index.html assets data` должен быть пустым.

## Закрытие от индексации и запуск

Пока сайт не запущен полностью, в `<head>` стоит `<meta name="robots" content="noindex">` с комментарием «убрать при полном запуске». Поисковики такую страницу не индексируют. **При полном запуске удалите эту строку вместе с комментарием.** Там же заданы заголовок, описание и Open Graph для красивой ссылки в мессенджерах (`og:url` и `og:image` указывают на `https://kickerwilder.github.io/novayaenergiya/`: при смене адреса сайта поменяйте их), иконка сайта лежит в `assets/favicon.svg`.

## Анимации при прокрутке

Блоки с классом `reveal` плавно появляются (сдвиг на 16 px и прозрачность, только `transform` и `opacity`). Скрытое состояние включается классом `js` на `<html>`, который ставит скрипт, поэтому без JS всё видно; при `prefers-reduced-motion: reduce` анимации отключены. Каталог при фильтрации перерисовывается без анимации: появляются только первые карточки при первом показе.

## Как опубликовать на GitHub Pages

1. Создайте репозиторий и загрузите в корень всё содержимое папки (index.html, assets, data, img, fonts).
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Через минуту сайт откроется по адресу `https://ваш-логин.github.io/название-репозитория/`.
